Ansible  은 내가 안써봤는데, 원래 어떤기능인데

Ansible은 쉽게 말하면 여러 서버에 해야 할 작업을 코드로 정의해두고, SSH를 통해 일괄 실행하는 자동화 도구입니다.

LiteDeck 관점으로 보면 꽤 비교가 잘 됩니다.

예를 들어 서버 20대에 nginx를 설치하고 실행해야 한다고 하면, 사람이 직접 SSH로 들어가서:

apt install nginx
systemctl enable nginx
systemctl start nginx

를 20번 하는 대신, Ansible에서는 이런 작업을 파일로 적어둡니다.

- hosts: webservers
  tasks:
    - name: nginx 설치
      apt:
        name: nginx
        state: present


    - name: nginx 실행
      service:
        name: nginx
        state: started
        enabled: yes

그리고:

ansible-playbook nginx.yml

한 번 실행하면 지정된 여러 서버에 SSH로 접속해서 알아서 적용합니다.

핵심 개념은 Playbook입니다. Playbook은 그냥 “서버에 어떤 상태를 만들 것인가”를 정의한 작업 파일입니다.

예를 들면:

웹 서버 그룹 10대
↓
nginx 설치되어 있어야 함
↓
설정 파일은 이 파일이어야 함
↓
서비스는 실행 중이어야 함

Ansible이 실제 서버를 확인한 다음 필요한 작업만 수행합니다.

그래서 중요한 특징이 멱등성(idempotency) 입니다.

예를 들어:

state: present

라고 하면 "apt install을 무조건 실행해라"가 아니라

nginx가 없으면 설치하고, 이미 있으면 아무 것도 하지 마라

라는 의미입니다.

이게 단순 SSH 스크립트와 차이가 큽니다.

LiteDeck과 비교하면 이런 느낌입니다.

LiteDeck	Ansible
사람이 서버 상태를 보고 조작	자동화 파일을 실행
GUI 중심	YAML 중심
서버 1~몇 대 직접 관리	수십~수천 대 관리
현재 상태 확인에 강함	원하는 상태 적용에 강함
클릭 → SSH 명령	Playbook → SSH 자동화
Interactive	Declarative / Automated

여기서 LiteDeck이 알아서 무리하게 merge해버리면 위험하고, git apply --3way 정도까지만 제공하고 conflict가 나면 기존 Git workflow로 넘기는 게 적당해 보입니다.

그리고 반대 방향도 자연스럽게 생깁니다.

Sync Local → Remote
Local repo


src/foo.cpp modified


[Send to Server]

그러면 commit/push/pull 과정 없이 SFTP로 해당 파일만 서버에 보내고:

[Build]

할 수도 있습니다.

그럼 개발 루프가:

Local 수정
   ↓
LiteDeck Send
   ↓
Server build
   ↓
실패
   ↓
Server 직접 수정
   ↓
성공
   ↓
Bring Back
   ↓
Local commit

이 됩니다.

이건 Git deployment라기보다 remote dev feedback loop가 되는 거죠.

그리고 아까 Saved Action 아이디어하고도 연결됩니다.

예:

[Build & Test]

Saved Action:

cd /opt/project
cmake --build build -j8
ctest --test-dir build

성공하면 LiteDeck이:

Build succeeded
3 remote files have changed


[Promote Changes]

보여주는 식.

그러면

AI → Action 생성 → 서버 작업 → 서버에서 hotfix → 변경분 회수 → Git push

가 하나의 workflow가 됩니다.

이건 그냥 SSH GUI 기능 추가 수준이 아니라 LiteDeck에 꽤 독특한 개발자 workflow가 생기는 것 같습니다.

제가 보기엔 이 기능은 상당히 괜찮습니다. 특히 서버 credential 없이 remote hotfix를 Git history로 안전하게 되돌려놓는 문제가 실제로 귀찮은 문제라서요.
